# Quickstart

## 1. Create the note layers

Set up the following directories before you begin reading and writing extensively:

- `references/`
- `concepts/`
- `claims/`
- `projects/`
- `indexes/`
- `templates/`
- `docs/`
- `memory/`

## 2. Name each paper consistently

Use a consistent file naming pattern such as:

`Author (Year) Title.pdf`

If you create a full-text markdown version, keep the same base name and swap the extension.

## 3. Start with source-faithful notes

For each paper, add a reference page that records:

- citation details
- research question
- sample and setting
- findings and mechanisms
- important limitations
- verification notes

## 4. Build concept pages

After a few readings, create concept notes that summarize the key idea in neutral academic language without turning it into a claim about your own project.

## 5. Write atomic claims

Claims should be small, specific, and traceable to the underlying literature. One claim should usually correspond to one carefully bounded argument.

## 6. Keep indexes light and navigable

Your indexes are not the place for deep writing. They are the wiki spine: a map of authors, concepts, projects, and references.

## 7. Re-check before publishing

Before citing a point in a paper or presentation, reopen the supporting source and confirm the wording, year, and interpretation.
